# Working on Datenfutter

Read `README.md`, `PLAN.md`, the relevant project README and source register before changing work. Retrieve the working Datenfutter folder through the Google Drive plugin when operating in ChatGPT; its link is in README. Current user instructions take precedence.

## Small verified changes

- Implement one coherent change per commit. Run the relevant checks before committing, push normally and verify the remote head/check result before adding another step.
- Start from a clean, current checkout. Stage explicit paths; do not force-push or commit downloads, caches or credentials.
- Update PLAN status with the implemented step. Distinguish local checks, remote checks, review and delivery. Do not copy old passing-test claims.
- Project changes require that project's checks; shared renderer/schema/brand changes require all migrated projects.
- Keep one active task branch from current main. Verify the integrated main SHA and its CI, then remove only the fully integrated task branch after rechecking ancestry. Fix failed gates on the same task before starting dependent work.
- Verify raw-to-table preparation in a disposable copy without saved processed tables. Compare full file sets and bytes; keep layout checks and production reproduction distinct.

## One current state

- Use `projects/<topic>/specs/<language>/<post>.json` and `projects/<topic>/posts/<language>/<post>/`. Keep one current PNG/SVG set, caption, alt text and manifest.
- Use ignored `build/` for temporary outputs. Do not retain old plot versions, dated export/preview folders or generated delivery ZIPs in Git.
- Keep immutable raw source bytes and original retrieval receipts. A refreshed dataset is a new retrieval; never change the timestamp on old evidence. A source ZIP is not an output backup.
- Before pruning a file, remove current build dependencies on it and verify its replacement. Drive cleanup follows verified migration and uses grounded file IDs.
- Store current review status with exact hashes. Successful rendering or migration does not invent user approval or social publication.

## Data and style

Use authoritative sources for every numerical and factual claim. Preserve definitions, units, missing observations, breaks, source vintage and exact URLs. Separate source acquisition from offline preparation and rendering. Share source/data work across languages only after checking vintages.

Preserve the existing design: 1080×1350; cream #FAF8EF; navy #1C2D57 accents; black general text; DejaVu Sans; existing circle-only df logo; bold navy 1/X; one descriptive block; lower-left Stand/As of. Keep approved A/B/C palettes. No navy header, added wordmark or extra interpretation paragraph. Captions include full literal source URLs.

Inspect current exports at full resolution and phone width with their complete captions before final delivery. Keep evidence checks, visual review and actual approval separate. Do not publish socially or change sharing settings without a request.
